## 1. 개요

K리그1·K리그2 모든 팀의 우승·승격·플레이오프 확률과 목표까지 남은 승점을 매일 자동으로 계산해 보여 주는 웹페이지다. 시즌 전체 경기 결과로 팀 전력을 추정하고, 남은 경기를 5만 번 시뮬레이션해 확률을 낸다.

| 항목 | 내용 |
| --- | --- |
| 이름 | K리그 우승·승격 확률 |
| 대상 사용자 | 시즌 막판 순위 싸움을 따라가는 K리그 팬 |
| 핵심 질문 | "우리 팀이 우승·승격·잔류할 확률은?", "몇 점 더 따면 확정인가?" |

## 2. 배경과 문제 정의

순위표는 현재 승점만 보여 주고, 팬이 정말 궁금한 "앞으로 어떻게 될까"에는 답하지 못한다. 시즌 막판에는 남은 일정, 상대 전력, 리그별 포스트시즌 규정이 한꺼번에 얽혀 머릿속 계산이 어렵다.

- **규정이 복잡하다**: K리그1은 33라운드 뒤 스플릿, 12위 승강 플레이오프(김천 상무 예외)가 있고, K리그2는 1·2위 자동 승격과 3~6위 플레이오프가 있다.
- **승점만으로는 일정의 난이도가 안 보인다**: 같은 승점이어도 남은 상대가 강팀인지 약팀인지에 따라 전망이 다르다.
- **"확정"과 "사실상 확정"이 섞인다**: 예를 들어 서울은 2위와 18점 차지만 수학적으로는 아직 우승 확정이 아니다.

이 프로그램은 세 가지를 해결한다. 팀별 목표 달성 확률을 숫자로 주고, 수학적 확정까지 남은 승점을 보여 주며, 모델이 실제로 얼마나 맞았는지 검증 결과를 함께 공개한다.

## 3. 주요 기능

사용자는 리그를 고르고, 현재 순위 순서로 모든 팀의 확률과 남은 승점을 한 표에서 본다.

| 기능 | K리그1 | K리그2 |
| --- | --- | --- |
| 확률 | 우승, ACLE권(1~2위), 파이널A(1~6위), 승강 PO | 우승, 자동 승격(1~2위), PO 진출(3~6위), 최종 승격 |
| 남은 승점 | 우승까지, 잔류까지 | 우승까지, 자동승격까지, PO권까지 |
| 팀 정보 | 최근 5경기, 예상 최종 승점 | 같음 |

화면 기능은 다음과 같다.

1. **리그 전환**: K리그1·K리그2 탭. 마지막에 본 리그를 기억한다.
2. **요약 카드**: 1위 팀의 우승까지 남은 승점, 우승 후보 1순위, 승강 PO·최종 승격 가능성 최고 팀, 남은 일정 수.
3. **확률 표**: 현재 순위 순. 확률은 막대로 표시하고, 마우스를 올리면 95% 오차 범위가 보인다.
4. **팀 상세**: 행을 누르면 남은 일정, 최근 5경기 점수, 추정 공격력·수비력, 부상·결장자, 최종 순위 분포가 펼쳐진다.
5. **확률 추이**: 날짜별 확률을 저장해 지표별 선 그래프(상위 6팀)로 보여 준다.
6. **백테스트**: 지난 시즌과 올 시즌 경기로 모델이 얼마나 맞았는지 보여 준다.
7. **다시 계산**: 평소에는 고정 시드로 같은 데이터면 같은 숫자가 나오고, 버튼으로 새 시드 결과를 볼 수 있다.
8. **갱신 멈춤 경고**: 데이터 기준일이 36시간 넘게 지나면 경고 배너를 띄운다.

## 4. 데이터

경기 데이터는 Daum 스포츠 일정 API 한 곳에서 시즌 전체를 받고, 순위표는 그 결과로 직접 계산한다. 2026년 10월 14일 기준 계산한 순위는 Daum 순위표와 두 리그 모두 일치했다.

| 항목 | 출처 | 내용 |
| --- | --- | --- |
| 경기 결과 | Daum 일정 API (`SPORTS_SCHEDULE`) | 날짜, 라운드, 홈·원정, 점수, 단계(정규·파이널A·B) |
| 남은 일정 | 같은 API | 경기 전·연기 경기 포함 |
| 순위표 | 경기 결과로 직접 계산 | 승점 → 다득점 → 득실차 → 다승 → 승자승 |
| 부상·결장자 | 최근 2주 뉴스 기사 | 기사로 확인된 주전급만, 출처·날짜 포함 |
| 백테스트용 지난 시즌 | Daum 일정 API | 2025시즌 K리그1 228경기, K리그2 273경기 |

**매일 갱신 흐름** (오전 7시경, Claude 앱 예약 작업)

1. `collect.py`가 두 리그 시즌 전체를 받아 순위표를 계산하고 검사한다.
2. Claude가 뉴스에서 부상·결장자를 찾아 `injuries.json`에 넣고, 스크립트를 다시 돌려 합친다.
3. Daum 순위표 페이지와 1~3위 승점을 대조한다.
4. 페이지 DB의 `leagues/k1`, `leagues/k2` 문서를 버전 확인 후 한 번에 덮어쓴다.
5. 페이지를 열어 그날 확률을 추이 기록에 남긴다(로그인된 경우만).

**검사 규칙**: 팀 수(K리그1 12, K리그2 17), 승점 = 3×승 + 무, 치른 경기 + 남은 경기 = 시즌 경기 수(K리그1 33 또는 38, K리그2 32). 하나라도 어긋나면 문서의 `note`에 문제를 적고 페이지가 사용자에게 보여 준다.

**부상자 정책**: 추측으로 채우지 않는다. K리그 데이터 포털(data.kleague.com)은 부상자 목록이 없고, 이용 약관상 자료 저장·배포가 제한되어 출처에서 제외했다.

## 5. 확률 모델

모델은 "시간 가중치를 둔 Dixon-Coles 포아송 모델 + 몬테카를로 시즌 시뮬레이션"이다. 머신러닝이 아니라 축구 데이터 분석에서 표준처럼 쓰이는 통계 모델이고, 계산은 페이지 안에서 직접 한다.

**득점 기대값**

```latex
\lambda_{\text{home}} = \mu \cdot h \cdot \alpha_{\text{home}} \cdot \beta_{\text{away}}, \qquad \lambda_{\text{away}} = \mu \cdot h^{-1} \cdot \alpha_{\text{away}} \cdot \beta_{\text{home}}
```

μ는 리그 평균 득점, h는 홈 배율, α는 공격력, β는 수비력(낮을수록 좋음)이다.

1. **상대 전력 보정**: 시즌 전체 결과에 가장 잘 맞는 α·β를 반복 계산(40회)으로 찾는다. 강팀을 상대로 넣은 골은 더 높게 평가된다.
2. **시간 가중치**: 경기 가중치는 180일마다 절반이 된다. 최근 흐름이 더 크게 반영된다.
3. **축소 추정**: 팀마다 리그 평균 수준의 가상 경기 8경기를 더해 우연을 줄인다.
4. **홈 배율**: 그 시즌 홈·원정 총득점 비율의 제곱근으로 정한다. 2026시즌은 K리그1 0.97, K리그2 1.04다.
5. **무승부 보정(Dixon-Coles)**: 0-0, 1-0, 0-1, 1-1 확률을 계수 ρ로 조정한다. ρ는 시즌 실제 무승부 수에 맞추며, 2026시즌은 K리그1 −0.27, K리그2 −0.28이다.
6. **불확실성**: 시뮬레이션마다 α·β를 로그 척도 표준오차(1/√근거 골 수)만큼 무작위로 흔든다.
7. **몬테카를로**: 남은 경기를 5만 번 치러 결과 횟수를 센다. 시드는 데이터에서 정해 같은 데이터면 같은 숫자가 나온다.

**대회 규정 반영**

| 규정 | 시뮬레이션 방식 |
| --- | --- |
| 순위 결정 | 승점 → 다득점 → 득실차 → 다승 → 승자승 → 추첨(벌점 데이터 없음) |
| K리그1 스플릿 | 33라운드 뒤 상·하위 6팀이 같은 그룹끼리 한 번씩. 일정 발표 전에는 시즌 홈 경기가 적은 팀이 홈 |
| K리그1 12위 | 승강 PO 출전. 김천 상무가 12위면 PO 없음 |
| K리그2 승격 | 1·2위 자동. 3대6, 4대5 단판 후 결승(상위 팀 홈, 무승부면 상위 팀) |
| 승강 PO | K리그1 12위 대 K리그2 PO 준우승, 홈 앤드 어웨이 2경기 합산 |

## 6. 검증 결과

경기 단위 예측은 단순 기준선보다 로그 손실 3.3%, 브라이어 점수 3.8% 좋았고, 무승부 비율은 예측 29.1% 대 실제 30.1%로 거의 맞았다. 축구 예측 모델로는 평범한 개선 폭이다.

**경기 단위 백테스트**: 2025·2026시즌 K리그1·2 742경기를 경기 당일 이전 결과만으로 다시 예측했다. 기준선은 그때까지 리그의 홈승·무·원정승 비율을 그대로 쓰는 예측이다.

**시즌 단위 백테스트**: 2025시즌을 같은 날짜(10월 14일) 시점에서 2만 번 시뮬레이션해 실제 최종 순위와 비교했다.

- **K리그2**: 인천 우승 98.2%, 수원 2위 이내 96.8%로 예측했고 실제로 그렇게 됐다. 브라이어 점수는 모델 0.038, "그날 순위가 그대로 간다" 기준선 0.048이다.
- **K리그1**: 전북 우승 99.7%, 대구 최하위 85.3%로 예측했고 둘 다 적중했다. 파이널A 마지막 자리는 강원 69.6%, 광주 30.4%로 보았고 실제로 강원이 들어갔다.

검증한 지난 시즌이 하나뿐이라 시즌 단위 결과는 참고용이다. 페이지의 "이 모델은 얼마나 맞았나" 섹션이 열 때마다 같은 검증을 다시 계산한다.

## 7. 화면 구성

한 페이지를 위에서 아래로 읽는 구조다. 요약을 먼저, 세부를 나중에 둔다.

1. **상단**: 제목, 데이터 기준일, 시뮬레이션 횟수, 출처, 리그 탭, "새 시드로 다시 계산" 버튼, 진행 막대.
2. **알림 배너**: 갱신 멈춤, 데이터 검사 문제, 부상자 정보 없음을 알린다.
3. **요약 카드 4장**.
4. **확률 표**: 순위 구간 색 띠(ACLE·파이널A·승강 PO / 자동 승격·PO), 팀 이름 열 고정, 넓으면 가로 스크롤.
5. **확률 추이**: 지표 탭 + 선 그래프.
6. **검증**: 경기 단위 지표, 보정 표, 지난 시즌 같은 날짜 예측 대 실제.
7. **계산 방법**: 모델과 가정을 평이하게 설명.

**표시 규칙**

| 상황 | 표시 |
| --- | --- |
| 수학적으로 확정 | "확정" (남은 승점 열은 "우승 확정", "잔류 확정" 등) |
| 수학적으로 불가능 | "불가" |
| 결정 안 됐고 99.95% 이상 | ">99.9%" (절대 100%로 표시하지 않음) |
| 결정 안 됐고 0.05% 미만 | "<0.1%" |
| 전승해도 경쟁 팀이 승점을 잃어야 함 | "자력 불가" |
| 김천 상무의 승강 PO·잔류 | "해당 없음" |

**남은 승점 계산**: k위 이내를 확정하려면, 경쟁 팀들의 최대 가능 승점 중 k번째로 큰 값보다 1점 더 따야 한다. 잔류는 김천을 버린 다른 팀 중 최대 가능 승점이 가장 낮은 팀보다 1점 더 따면 확정이다.

## 8. 시스템 구조와 운영

수집은 사용자 PC에서, 저장과 계산은 claude.ai 아티팩트에서 한다. 확률 계산은 서버가 아니라 페이지를 연 브라우저에서 일어난다.

[embed: node/4e401849-95c7]

| 구성 요소 | 위치 | 역할 |
| --- | --- | --- |
| `collect.py` | `kleague-odds/` 폴더 | Daum API에서 시즌 수집, 순위 계산, 검사, JSON 저장. `--history 2025`로 지난 시즌 수집 |
| `engine.js` | `kleague-odds/` 폴더 | 전력 추정, Dixon-Coles, 시뮬레이션, 백테스트. 파라미터(PARAMS) 보관 |
| `page.html` | `kleague-odds/` 폴더 | 화면 틀과 표시 로직 |
| `build.py` | `kleague-odds/` 폴더 | 엔진을 페이지에 합쳐 `kleague-odds.html` 생성. `--test`로 로컬 확인용 페이지 생성 |
| `calibrate.html` | `kleague-odds/` 폴더 | 파라미터 격자 탐색용 |
| 페이지 DB | claude.ai 아티팩트 | `leagues/k1`, `leagues/k2`, `seasons/k1-2025`, `seasons/k2-2025`, `history/<날짜>` |
| 예약 작업 | Claude 앱 (매일 07:10) | 수집 → 부상 조사 → 검사 → 저장 → 추이 기록 |

**접근 권한**: 페이지는 비공개다. DB는 페이지를 볼 수 있는 사람은 읽고, 쓰기는 페이지 주인만 한다. 다른 사람에게 보여 주려면 페이지의 Share 메뉴에서 공유한다.

**운영 절차**

1. 모델을 고칠 때: `engine.js` 수정 → `build.py --test`로 로컬 확인 → `build.py` → 페이지 게시.
2. 파라미터를 다시 맞출 때: `calibrate.html`에서 격자 탐색 → 가장 낮은 로그 손실 값을 `PARAMS`에 반영.
3. 새 시즌이 시작될 때: `collect.py`의 `FORMATS`에 새 시즌 형식 추가 → 지난 시즌을 `-history`로 수집해 `seasons` 문서 교체.

## 9. 한계와 리스크

가장 큰 리스크는 데이터 갱신이 사용자 PC의 Claude 앱에 의존한다는 점과, 검증 못 한 가정 3개가 남아 있다는 점이다.

| 리스크 | 영향 | 현재 대응 |
| --- | --- | --- |
| 예약 작업은 Claude 앱이 켜져 있어야 실행 | 데이터가 멈춘 채 확률이 표시됨 | 36시간 넘으면 경고 배너 |
| 데이터 출처가 Daum 한 곳 | API 구조가 바뀌면 수집 실패 | 검사 규칙 + Daum 순위표 대조, 문제는 페이지에 표시 |
| 승점 감점 등 행정 조치 | 경기 결과로 계산한 순위와 달라짐 | 매일 순위표 대조, 다르면 보고 |
| 부상·결장자 정보 공백 | 주전 결장이 확률에 반영 안 됨 | 뉴스로 확인된 경우만 반영, 없으면 페이지에 안내 |
| 검증 안 된 가정 3개 | 승강 PO·부상 보정이 틀릴 수 있음 | 페이지에 "가정"으로 명시 |
| 벌점 동점 규정 미반영 | 드물게 동률 팀 순서가 다를 수 있음 | 추첨으로 대체, 명시 |
| 파이널 라운드 홈·원정 추정 | 일정 발표 전 확률이 약간 다를 수 있음 | 발표되면 실제 일정 사용 |
| 홈 승리 과대 예측 | 홈 승률 40% 이상 구간에서 3~6%p 높게 예측 | 다음 개선 대상 |
| 확률 추이 기록 누락 | 페이지를 열지 않은 날은 기록 없음 | 예약 작업이 페이지를 열도록 시도 |

이 확률은 추정치이며 베팅·투자 판단용이 아니다. 페이지에도 "재미로 보는 추정치"라고 적어 둔다.

## 10. 향후 계획

우선순위는 정확도에 가장 크게 영향을 주는 것부터 정했다. 일정은 아직 정하지 않았다.

1. **갱신 안정화**: PC 없이 도는 클라우드 예약 작업으로 옮기고, 실패 시 알림을 보낸다.
2. **확률 추이 자동 기록**: 예약 작업이 시뮬레이션까지 직접 돌려 매일 기록하게 한다.
3. **홈 승리 과대 예측 보정**: 홈 배율을 팀별로 두거나 보정 곡선을 적용한다.
4. **검증 범위 확대**: 2023·2024시즌을 추가해 백테스트 표본을 늘리고, 승강 PO 가정(0.85배, 45%)을 실제 승강 PO 결과로 맞춘다.
5. **두 번째 데이터 출처**: K리그 공식 사이트 순위와 자동 대조한다.
6. **부상·결장 정보 개선**: 구단 공지·경기 명단 등 이용 가능한 출처를 찾고, 결장 영향을 선수 출전 시간·공격 포인트로 추정한다.
7. **ACL 출전권 규정**: 코리아컵 우승팀에 따른 출전권 이동을 반영한다.
8. **공유 기능**: 팀별 확률 카드를 이미지로 저장하거나, 링크로 팀을 바로 열 수 있게 한다.)
